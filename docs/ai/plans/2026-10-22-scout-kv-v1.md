# scout_kv v1 (body/tail position flag) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Train and gate `scout_kv` v1: v0's per-layer WGAN-GP with a body/tail flag on generator and critic, piloted at L19 and L43 before the other 10 layers.

**Architecture:** The flag is a one-hot of width 2 (0 = body, 1 = tail) concatenated to the generator's latent input and to the critic's input, by thin wrapper modules that `build_generator` / `build_critic` return when `model.n_flags` is set. The loader derives each row's flag from its position. The trainer draws each batch as a fixed body/tail mix from two loaders, gives fakes the same flags as the real batch, and scores checkpoints per flag. `kv_gate` samples keys under the body flag and both query sets under the tail flag. Every path without `n_flags` is unchanged.

**Tech Stack:** Python 3, PyTorch, numpy, faiss (gate), pytest; box runs on `tig-gpu-alt` (L40, `/workspace/kvenv`).

**Spec:** `docs/ai/specs/2026-10-22-scout-kv-v1-position-flag-design.md` (builds on `docs/ai/specs/2026-10-18-kv-cache-scout-design.md`). Read both.

## Decisions this plan makes (spec items left to the builder)

| item | decision | why |
|---|---|---|
| how the flag enters (spec item 3) | one-hot width 2 concatenated to generator input (`latent_dim + 2`) and critic input (`descriptor_dim + 2`); only `generator_type: mlp` and `critic_type: per_vector` accept `n_flags` | smallest change that reuses v0's exact MLP classes, so the flag is the only difference |
| tail oversampling (item 5) | `tail_batch_share: 0.25`: 128 tail + 384 body rows per 512-row batch | tail rows are 3% of training rows, too little critic signal. A share of 0.5 would reuse each tail row about 2,700 times over a run, against 159 for a v0 row. At 0.25 a tail row is reused about 1,360 times and a body row about 123 times (ESTIMATE (unverified), arithmetic: 120,000 batches × 128 / 11,264 tail rows; × 384 / 373,298 body rows). Per-flag Wasserstein is logged so critic overfitting on the tail shows up |
| holdout (item 2) | body: `holdout_fraction` 0.02 of body rows (7,618); tail: `kv_tail_holdout` 1,024 rows, a count | 2% of tail would be ~245 rows, too few for the selector's k = 100 |
| selection (item 4) | `selection_score = selection_score(body) + selection_score(tail)`, each against its own holdout class; `select_on: cov_fro` with `n_flags` is refused | a pooled score is ~97% body. Whether the tail half is above noise is measured in B1, and the final checkpoint is gated as well as best, so a weak selector cannot hide a good final checkpoint |
| fake flags in the critic step | fakes take the real batch's flags, so the gradient penalty interpolates rows with the same flag | spec item 3 constraint |
| pilot measurement | v1 best and final at `--seed 0` and `--seed 1`; v0 best re-measured at `--seed 1` | spec "Pilot" step 2 |
| judging | a pure module `src/kv/judge.py` implements the spec's "toward real" rule and is unit-tested on the spec's own numbers | the go/no-go must not be judged by eye |

### Task 7: The "toward real" judge

**Files:**
- Create: `src/kv/judge.py`
- Test: `tests/test_scout_kv_judge.py`

**Interfaces:**
- Consumes: `pooled_statistics`, `STATISTICS` from `src/eval/kv_gate.py`.
- Produces:
  - `distance(value: float, lo: float | None, hi: float | None) -> float`: 0 inside `[lo, hi]` (inclusive), else the gap to the nearer edge. A `None` bound is open.
  - `moves_toward(v1: float, v0: float, lo, hi, spread: float) -> bool`: `distance(v1) == 0 or distance(v1) < distance(v0) - spread`.
  - `is_borderline(v1, v0, lo, hi, spread) -> bool`: moves, not inside, and `distance(v0) - distance(v1) < 2 * spread`.
  - `train_books_targets(path: Path, layer: int) -> dict[str, float]`: pooled statistics of `docs/results/scout-kv/controls/train_books_real.jsonl` at one layer (books 0-7). Read from the file, not hard-coded; the test pins the values.
  - `pilot_verdict(v1_by_seed: dict[int, list[dict]], v0_by_seed: dict[int, list[dict]], references: list[list[dict]], train_books: list[dict]) -> dict`: per layer in {19, 43}, per statistic in (`ivf_ratio_k128`, `hnsw_reach_k10`, `hnsw_recall_k10_ef176`), it gives `moves` and `borderline`. Seeds are **paired**: v1 at seed s is compared with v0 at seed s, and `moves` is true only if it holds at every seed in `v1_by_seed` (which must equal `v0_by_seed`'s keys, else `ValueError`). Per-layer values are `pooled_statistics` of that layer's records. At L19 the target interval is widened to include the train-books value. Key-side recall gets `not_lower` = for every seed s, v1_s ≥ v0_s − (max − min of v0 over seeds at that layer). The top-level `go` is the AND over both layers of the three `moves` and `not_lower`. It is computed for one checkpoint kind at a time; the caller passes best or final.
  - `full_verdict(v1: list[dict], v0_by_seed: dict[int, list[dict]], references, bands: dict) -> dict`: pooled, every statistic, the band as the target, v1 compared with v0 at seed 0. The spread is the pooled reference spread, except for `hnsw_recall_k10_ef176_id`, whose reference spread is 0: its allowance is v0's own pooled max − min across the seeds in `v0_by_seed` (spec, "Key-side recall"). For `ivf_recall_k128_np24` the requirement is "stays inside the band". The result also carries the band pass/fail per statistic.
  - CLI: `python -m src.kv.judge pilot --v1 SEED=PATH [--v1 ...] --v0 SEED=PATH [--v0 ...] --out verdict.json` and `python -m src.kv.judge full --v1 PATH --v0 SEED=PATH [--v0 ...] --out verdict.json`. `--references` defaults to `docs/results/scout-kv/reference/seed{0..4}.jsonl`, `--train-books` to `docs/results/scout-kv/controls/train_books_real.jsonl`, `--gate-file` to `gates/scout_kv.yaml`, all resolved from the repo root.
