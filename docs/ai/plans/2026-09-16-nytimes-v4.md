# NYTimes v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn on the log-ratio regulariser for the NYTimes family as rung `v4`, so the local neighbourhood geometry `v3` reaches at step 9,000 is held for the whole run instead of decaying.

**Architecture:** One change from `v3`: three `lid_reg` keys in `training`. Alpha is measured by `tools/probes/lid_reg_scale_probe.py` on this family before the config is written, not carried over from SIFT. Running that probe first requires two fixes to it. Nothing else — generator, critic, selector, radius band, seed and step budget are untouched, so `v4` pairs exactly against the existing `v3_seed42` run.

**Tech Stack:** Python 3.12, PyTorch, PyYAML, pytest, ruff. Training and probes run on `tig-gpu` through `gpuq`.

**Spec:** `docs/ai/specs/2026-09-16-nytimes-v4-local-profile-design.md`

## Global Constraints

- **One change only.** `v4.yaml` differs from `v3.yaml` in exactly `training.lid_reg_alpha`, `training.lid_reg_k`, `training.lid_reg_max_points`, and `output_dir`. Any other drift is a bug, and Task 4's test catches it.
- **`lid_reg_k: 20`**, not the gate's 100. Deliberate; see the spec's "Why `k = 20` and not `100`".
- **`lid_reg_max_points: 256`.**
- **Do not add a `device:` key to any config.** Every NYTimes config says `device: auto` and that trains correctly on the box. Adding one would make this a two-change rung.
- **Never submit a training job with `--vram-mb`.** It lets the scheduler admit a second job onto the card, which then dies on `train_wgan_gp`'s per-card lock after 1800 s.
- **Never declare a `runs/...` path as `--artifact`.** `runs/` is gitignored and the runner collects artifacts with `git add`, which errors on an ignored path; the job is then marked failed with `exit_code: 0`. Copy to `/workspace/...` inside the job instead.
- **Interpreter on the box is `/venv/main/bin/python`.** The 2026-09-16 rebuild removed `/opt/venvs/wgan-synthetic`.
- **`make check` must pass** before every commit: `ruff check src tests`, `ruff format --check src tests`, `pytest`. One pre-existing failure is expected and unrelated: `tests/test_contract.py::test_contract_holds_at_declared_level` fails because the installed `agentify` supports contract level 1 while the repo declares 2. ### Task 1: Make the sizing probe usable on this family

`tools/probes/lid_reg_scale_probe.py` has two defects that block it on NYTimes configs. Line 77 is `device = torch.device(cfg["device"] if torch.cuda.is_available() else "cpu")`. It cannot parse `device: auto` (`torch.device("auto")` raises `RuntimeError`), and it has no way to stay off the card, so a `--lane cpu` job would allocate on the GPU beside whatever holds the per-card lock. It also has no `--output`, unlike every other probe in `tools/probes/`, so its result cannot be committed as JSON.

**Files:**

- Test: `tests/test_lid_reg_scale_probe.py` (create)

**Interfaces:**
- Consumes: `src.device.resolve_device(device_cfg: str, *, strict: bool = False) -> torch.device` (exists)
- Produces: `resolve_probe_device(cfg: dict, device_arg: str | None) -> torch.device`, used by Task 2's job script via the `--device` flag; and a `--output PATH` that writes the result dict as JSON.

- [ ] **Step 1: Write the failing test**

Create `tests/test_lid_reg_scale_probe.py`:

```python
"""The sizing probe must run against this project's configs and stay where it
is told.

Every NYTimes config says `device: auto`, which `torch.device` cannot parse --
only `src.device.resolve_device` handles it. And a probe that picks its device
from the config alone takes the GPU even when submitted to the cpu lane, which
is the collision the queue exists to prevent.
"""

from __future__ import annotations

import importlib.util
from pathlib import Path

import pytest
import torch

_SPEC = importlib.util.spec_from_file_location(
    "lid_reg_scale_probe",
    Path(__file__).resolve().parents[1] / "tools" / "probes" / "lid_reg_scale_probe.py",
)
probe = importlib.util.module_from_spec(_SPEC)
_SPEC.loader.exec_module(probe)


def test_auto_config_resolves_without_raising():
    """Catches torch.device(cfg["device"]) coming back: it raises on "auto"."""
    got = probe.resolve_probe_device({"device": "auto"}, None)
    assert isinstance(got, torch.device)


def test_delegates_to_resolve_device(monkeypatch):
    """Catches a fix that special-cases the string "auto" in the probe instead
    of delegating, and catches passing strict=True.

    Comparing return values cannot catch either: on a CPU-only host -- which
    is what CI is -- resolve_device("auto") and a hand-rolled `if auto: cpu`
    both return cpu, and strict never fires because it sits behind a
    cuda.is_available() check. Only observing the call discriminates.
    """
    seen = {}

    def fake(device_cfg, **kwargs):
        seen["cfg"] = device_cfg
        seen["kwargs"] = kwargs
        return torch.device("cpu")

    monkeypatch.setattr(probe, "resolve_device", fake)
    probe.resolve_probe_device({"device": "auto"}, None)
    assert seen["cfg"] == "auto"
    assert seen["kwargs"].get("strict", False) is False


def test_device_argument_overrides_the_config():
    """Catches an override that is parsed but ignored, which would put a
    cpu-lane job on the card."""
    got = probe.resolve_probe_device({"device": "cuda:0"}, "cpu")
    assert got == torch.device("cpu")


def test_config_is_used_when_no_override_is_given():
    """Catches an override that always wins, which would ignore the config."""
    got = probe.resolve_probe_device({"device": "cpu"}, None)
    assert got == torch.device("cpu")
```

### Task 2: Measure `lid_reg_alpha` on this family

The probe needs a config carrying `lid_reg_k`, `lid_reg_max_points` and `batch_size`. `v4.yaml` does not exist yet and must not be written with a guessed alpha, so the job builds a throwaway sizing config from `v3_seed42.yaml` on the box. That keeps the committed `v4.yaml` born with a measured value, and the generation is deterministic from a version-controlled script.

**Files:**
- Create: `scripts/nytimes_v4_lid_reg_scale_job.sh`
- Create (from the job's output): `docs/results/nytimes-v4-lid-reg-scale/lid_reg_scale.json`, `docs/results/nytimes-v4-lid-reg-scale/job_spec.json`

**Interfaces:**
- Consumes: `--device`, `--output` from Task 1.
- Produces: `suggested_alpha` (float) in `lid_reg_scale.json`, plus `floor`, `v3init` and `v2` (the trained-generator gap). Task 3 writes `suggested_alpha` into `v4.yaml` and quotes `floor`/`v2` in the comment beside it.

- [ ] **Step 1: Write the job script**

Create `scripts/nytimes_v4_lid_reg_scale_job.sh`:

```bash
#!/usr/bin/env bash
# One gpuq job: size lid_reg_alpha for the NYTimes family, before v4 exists.
#
#   gpuq submit --project wgan-synthetic --commit <sha> --branch nytimes-v4 \
#     --lane cpu --timeout-s 3600 -- bash scripts/nytimes_v4_lid_reg_scale_job.sh
#
# cpu lane and --device cpu: this takes no card lock and must not allocate on
# the GPU, so it can run beside whatever is training. Do NOT pass --vram-mb.
#
# The sizing config is built here rather than committed, because alpha is what
# this job measures: committing a config with a guessed alpha first, then
# amending it, would leave a provisional number in history that someone could
# train from. The probe reads only batch_size, lid_reg_k, lid_reg_max_points,
# the model block, descriptor_dim, real_path and device, so v3_seed42 plus the
# two k keys is a faithful stand-in for v4.
set -euo pipefail
P=${WGAN_PYTHON:-/venv/main/bin/python}
V3=/workspace/nytimes-v3/v3_seed42
REAL=/workspace/data-cache/nytimes_250k.npy
CFG=/tmp/nytimes_v4_sizing.yaml
OUT=runs/nytimes/probes/lid_reg_scale.json
KEEP=/workspace/nytimes-v4/probes

test -f "$P"
test -f "$REAL"
test -f "$V3/checkpoint_step_9000.pt"
test -f configs/nytimes/v3_seed42.yaml

# real_path stays the RAW corpus, the same file the trainer loads: the penalty
# has to be sized against the distribution it will actually see. The trainer
# drops 197 exact-zero rows at load and keeps duplicates; this probe drops
# neither, but log_ratio_penalty's own survivor mask discards the degenerate
# rows (r_1 == 0, r_1 == r_k) from the estimate either way. Do not silently
# switch this to the cleaned corpus -- that file also has 31,949 duplicates
# removed, which changes a local-neighbourhood statistic.
"$P" - "$CFG" <<'PY'
import sys, yaml
cfg = yaml.safe_load(open("configs/nytimes/v3_seed42.yaml"))
cfg["training"]["lid_reg_k"] = 20
cfg["training"]["lid_reg_max_points"] = 256
yaml.safe_dump(cfg, open(sys.argv[1], "w"), sort_keys=False)
print(f"wrote {sys.argv[1]}")
PY

# --adv-loss 0.87 is v3's run-mean |adv_loss| (MEASURED, from the committed
# docs/results/nytimes-v3/run_metadata.json). Sizing at launch instead would
# use the first-20-step mean of 0.33 and oversize alpha roughly threefold; the
# penalty has to do its work in the collapse window, not at initialisation.
# The trained reference is v3's step-9,000 checkpoint for the same reason.
"$P" tools/probes/lid_reg_scale_probe.py \
  --config "$CFG" \
  --device cpu \
  --v2-checkpoint "$V3/checkpoint_step_9000.pt" \
  --v2-config configs/nytimes/v3_seed42.yaml \
  --adv-loss 0.87 \
  --target-fraction 0.05 \
  --output "$OUT"

mkdir -p "$KEEP" && cp "$OUT" "$KEEP"/ && sha256sum "$KEEP"/lid_reg_scale.json
```

**Spec coverage.** Every spec section maps to a task: the one change and its three keys → Task 3, pinned by Task 4; `k = 20` rationale → Task 3's comment and Task 4's assertion; alpha sizing with its two departures from the probe's defaults → Task 2; both probe bugs → Task 1; configs and scripts → Task 3; the tests table → Tasks 1 and 4; mechanism checks → Task 6 Step 3; success criteria → Task 6; fallbacks → Task 6's closing paragraph; "what this does not do" → Task 4's `test_v4_keeps_distance_reg_off` and the global constraints.

**Deliberate omission.** The spec says alpha must not be pinned by a test, because a test asserting a specific float pins a measurement rather than a contract. Task 4 therefore asserts alpha is positive and is traceable to the probe — never its exact number. An earlier draft also asserted `alpha != 0.015` to catch SIFT's value being pasted in; the audit removed it, because the measured alpha could legitimately land on 0.015 and the test would then fail a correct config. The traceability assertion covers the same intent without that false positive, at the cost of not catching a pasted value that kept the comment — a gap noted rather than papered over.

**Audit fixes carried into this plan.** One Critical: Task 5 retrieved `eda_clean/eda_clean_summary.json`, which does not exist — `eda_report` writes `summary.json` and the committed name is a rename on arrival, so the `tar` would have failed. Three Nits recorded inline: the probe's silent 200k-row pool cap, `--dedupe-key` returning the old job on a same-commit resubmit, and parsing the trainer's JSON log instead of grepping it.

**Flagged, deliberately not fixed.** `lid_reg_scale_probe.py` guards its alpha suggestion with `if args.adv_loss:`, a falsy-zero test that would skip on `--adv-loss 0`. Zero is not a meaningful adversarial loss, the plan passes 0.87, and touching it would widen this rung's diff for no gain.
