Architecture caveat
Dense can flatter

v1/v1_5 cannot emit exact zeros. Their close ANN aggregates do not mean they reproduce SIFT's support; support diagnostics explain the mismatch.

Objective caveat
v4 LID is fitted

v4 trains on LID's sufficient statistic. Its LID movement confirms the penalty worked, but contrast, hubness, and Gini carry the independent evidence.

How memory metrics relate to ANN deployment

Model baseline is device memory already allocated after building and warming the generator. Sampling peak above baseline isolates the temporary tensors needed to produce one batch; this is the useful figure for deciding whether generation can coexist with a GPU ANN index. Peak reserved includes memory retained by PyTorch’s caching allocator and is not the same as live tensor memory; see PyTorch’s CUDA memory-management notes. Host output is the float32 corpus handed to a CPU ANN index: N × 128 × 4 bytes.

How runtime metrics relate to ANN deployment

GPU generation is the time to create and normalize the corpus before an ANN index can ingest it. CUDA work is asynchronous, so every region is fenced with PyTorch synchronization.

To host + assembly is paid when a CPU ANN index needs a NumPy corpus; an on-GPU index can avoid it. PyTorch’s CUDA semantics explain why device/host copies form a separate boundary.

p95 budget is the conservative generation-plus-host deadline: 95% of observed repeats should fall at or below it. It is an operational tail-latency measure, not an ANN-quality statistic.

CUDA initialization adds 0.270 s once per process. Build and warmup are separate from the plotted per-instance budget. Host timing drops sharply at v1/800k and v4/700k, then rises again in the separately measured 1M cells; do not fit one host-transfer slope through those discontinuities.
